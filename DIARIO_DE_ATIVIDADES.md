# Diário de Atividades

Registro cronológico das contribuições e atividades do projeto **O Infinito que se Experimenta**.

Cada entrada deve preservar o que efetivamente aconteceu no projeto, distinguindo fatos registrados de análises e interpretações posteriores.

---

## Protocolo oficial do Diário

### 1. Quando registrar

Uma atividade deve ser registrada sempre que o **Capitão solicitar explicitamente o registro** de uma ação, descoberta, decisão, hipótese, análise, contribuição, alteração metodológica ou outro acontecimento relevante do projeto.

O diário não deve ser usado para inventar atividades que não ocorreram.

### 2. Ordem obrigatória

Quando o Capitão solicitar que algo seja registrado, a ordem operacional é:

**REGISTRAR → CONFIRMAR O REGISTRO → ANALISAR / OPINAR.**

A análise do Subcomandante nunca deve substituir o registro histórico.

Quando tecnicamente possível, o arquivo deve ser atualizado antes que a análise seja apresentada na conversa.

### 3. Separação entre registro e interpretação

Cada entrada deve distinguir claramente:

- **Fato/atividade:** o que foi feito, decidido, encontrado ou dito.
- **Contribuidor:** quem realizou ou propôs a atividade.
- **Tipo:** pesquisa, hipótese, decisão, metodologia, revisão, desenvolvimento, documentação etc.
- **Arquivos afetados:** arquivos modificados ou criados, quando aplicável.
- **Resumo:** descrição objetiva do acontecimento.
- **Observação/análise:** interpretação posterior, somente quando fizer sentido.

Uma opinião do Subcomandante não deve ser registrada como se fosse um fato histórico.

### 4. Integridade histórica

Entradas antigas não devem ser silenciosamente reescritas para adequá-las a conclusões posteriores.

Se uma hipótese mudar, deve-se registrar uma nova entrada explicando a mudança.

Se uma conclusão anterior for considerada incorreta, ela permanece no histórico como uma conclusão anterior e recebe uma nova entrada de revisão.

### 5. Data e horário

As entradas devem utilizar a data e o horário do registro no fuso **UTC-03 (Brasil)**, quando disponíveis.

### 6. Identificação dos contribuidores

As contribuições devem ser atribuídas corretamente.

Estrutura atual:

- **Capitão:** idealizador e autoridade autoral humana do projeto.
- **ChatGPT:** Subcomandante; responsável por organização, modelagem, investigação e desenvolvimento quando atuando nessas funções.
- **Grok:** contribuidor e segunda opinião independente.
- **Demais participantes:** contribuidores, identificados individualmente quando possível.

A atribuição deve descrever a contribuição efetivamente realizada, sem atribuir a um participante trabalho que não executou.

### 7. Discordâncias

Discordâncias entre participantes devem ser preservadas, e não apagadas para produzir uma narrativa artificialmente consensual.

Quando houver posições diferentes, o diário deve registrar a divergência e, se relevante, apontar para o arquivo onde a análise comparativa será desenvolvida.

### 8. Fontes e evidências

Quando uma atividade envolver pesquisa, a entrada deve registrar a fonte ou referência quando disponível.

O diário registra **que uma evidência foi encontrada**; a avaliação de sua força deve ocorrer nos documentos de pesquisa/evidência apropriados.

### 9. Hipóteses não são fatos

Formulações como “pode ser”, “acreditamos”, “propomos” e “hipoteticamente” devem permanecer claramente identificadas como hipóteses quando não houver evidência suficiente.

Nenhuma contribuição de IA deve ser convertida automaticamente em fato histórico, científico, bíblico ou teológico.

### 10. Regra de auditoria

O diário deve permitir que, no futuro, qualquer participante consiga responder:

1. O que aconteceu?
2. Quando aconteceu?
3. Quem contribuiu?
4. Qual arquivo foi alterado?
5. Qual era a interpretação naquele momento?
6. O que mudou depois?

A finalidade é preservar uma trilha intelectual auditável da evolução do projeto.
